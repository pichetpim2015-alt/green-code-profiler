# 🌱 Green Code Profiler — เครื่องมือวัดความประหยัดพลังงานของโค้ด

> **ให้ "เกรด A–F" กับโค้ดของคุณ เหมือนฉลากประหยัดไฟเบอร์ 5**
> วัดว่าอัลกอริทึมแต่ละแบบใช้เวลา หน่วยความจำ พลังงาน และปล่อยคาร์บอนเท่าไร แล้วบอกว่า "ประหยัด" หรือ "เปลือง"

*A simple tool that measures how much time, memory, energy, and CO₂ an algorithm uses — then gives it an A–F sustainability grade, like an energy-efficiency label for code.*

โครงงานวิชา IS2 (การสื่อสารและการนำเสนอ) · โรงเรียนขอนแก่นวิทยายน · ปีการศึกษา 2569
พัฒนาด้วย **Python** · ทำงานบน Windows / macOS / Linux · เป็นซอฟต์แวร์โอเพนซอร์ส (ฟรี)

---

## 🎯 ปัญหาที่แก้ (The Problem)

ทุกครั้งที่โปรแกรมทำงาน มันกินไฟฟ้าและหน่วยความจำ แต่คนเขียนโค้ดส่วนใหญ่ **มองไม่เห็น** ว่าโค้ดของตัวเองเปลืองแค่ไหน และไม่มีเครื่องมือง่าย ๆ ที่บอกออกมาเป็น "ค่าไฟ" หรือ "คาร์บอน" ที่เข้าใจได้ทันที การเลือกอัลกอริทึมที่ไม่ดีจึงทำให้สิ้นเปลืองพลังงานโดยไม่จำเป็น ซึ่งเมื่อคูณด้วยผู้ใช้จำนวนมาก กลายเป็นการปล่อยคาร์บอนมหาศาล

**Green Code Profiler** แก้ปัญหานี้ด้วยวิธีที่เรียบง่าย: วัดโค้ด → แปลงเป็นพลังงาน/คาร์บอน → ให้เกรด A–F ที่ใครก็เข้าใจ

---

## ✨ ทำอะไรได้บ้าง (Features)

- ⏱️ **วัดเวลา (Latency)** ระดับนาโนวินาที และ **หน่วยความจำ (RAM)** ที่โค้ดใช้จริง
- 🔋 **แปลงเป็นพลังงาน (จูล)** และ **คาร์บอน (gCO₂e)** ตามมาตรฐาน Software Carbon Intensity
- 🏷️ **ให้เกรด A–F** ตามอัตราการเติบโตของทรัพยากร (เหมือนฉลากเบอร์ 5)
- 📊 **แดชบอร์ดบนเว็บ** แสดงผลแบบเรียลไทม์
- ✅ **พิสูจน์ความแม่นยำ** ได้เอง โดยเทียบกับตัวนับของระบบปฏิบัติการ (R² = 1.00)
- 🔬 **ควบคุมความคลาดเคลื่อน** ด้วยการทดสอบซ้ำ 30 รอบ ลบค่าฐาน และตัดค่าผิดปกติ

```
│  (เว็บแดชบอร์ด: กราฟเวลา/แรม/พลังงาน/เกรด)          │
└───────────────────────▲────────────────────────┘
┌───────────────────────┴────────────────────────┐
│  ชั้นที่ 2: คำนวณ    green_metrics.py             │

└────────────────────────────────────────────────┘
```

## 📊 ผลการทดลอง (Results)

เปรียบเทียบอัลกอริทึม "แบบธรรมดา" กับ "แบบฉลาด" 3 คู่ ที่ข้อมูล 100 / 1,000 / 10,000 ตัว
(วัดจริงบน Intel Core i5-1235U, Windows 11, ค่าไฟฟ้าไทย 500 gCO₂e/kWh)

| คู่ที่ทดสอบ | ที่ข้อมูล 10,000 ตัว | ประหยัดพลังงาน | เกรด |
|---|---|---|---|
| Bubble → Quick Sort | เร็วขึ้น **312 เท่า** | **99.68%** | D → C |
| Linear → Binary Search | เร็วขึ้น ~174 เท่า | **99.42%** | C → B |
| Fibonacci เรียกซ้ำ → จำค่าไว้ | เร็วขึ้น ~590,000 เท่า | **99.99%** | F → C |

**กราฟการเติบโตของเวลาเมื่อข้อมูลเพิ่มขึ้น** (เส้นชันกว่า = เปลืองกว่า)

![กราฟ scaling](results/figures/fig1_scaling_loglog.png)

**ผลที่วัดได้ตรงกับทฤษฎี Big-O** (จุดสีน้ำเงินคือค่าที่วัดได้ ตรงกับที่ทฤษฎีทำนาย)

![Big-O validation](results/figures/fig2_bigO_validation.png)

**ผลด้านการประหยัด** — เปลี่ยน Bubble → Quick Sort ที่ระดับเรียกใช้ 1 ล้านครั้ง/วัน ประหยัดได้ ~854 หน่วยไฟ/ปี หรือ ~0.43 ตัน CO₂e/ปี

![headline savings](results/figures/fig3_headline_savings.png)

## 🚀 การติดตั้งและใช้งาน (Quick Start)

**1. ติดตั้ง Python 3.9+ แล้วติดตั้งไลบรารีที่จำเป็น**

```bash
pip install -r requirements.txt
```

**2. รันการทดลองเปรียบเทียบอัลกอริทึม** (สร้างไฟล์ผลลัพธ์ในโฟลเดอร์ `results/`)

```bash
python algo_lab.py --budget 8 --cores 10 --tdp 15 --grid 500
```
> `--cores` = จำนวนแกน CPU · `--tdp` = กำลังไฟ CPU (วัตต์) · `--grid` = ค่าคาร์บอนของไฟฟ้า (ไทย = 500)
> เพิ่ม `--quick` เพื่อรันแบบเร็ว

**3. เปิดแดชบอร์ดบนเว็บ**

```bash
python perf_bench_server.py --host 127.0.0.1 --port 5000
```
แล้วเปิดเบราว์เซอร์ไปที่ `http://127.0.0.1:5000`

**4. สร้างกราฟจากผลการทดลอง**

```bash
python make_figures.py
```

## 📌 วัดโปรแกรมของคุณเอง (Measure Your Own Program)

เครื่องมือนี้ **วัด “โปรแกรมที่กำลังทำงาน” ไม่ใช่ไฟล์โค้ดเฉย ๆ** — คุณต้องบอก *“คำสั่งที่ใช้รันโปรแกรม”* ให้มัน โดยมี 2 โหมด:

**โหมด A — เปรียบเทียบอัลกอริทึมสำเร็จรูป** (รันได้ทันที ไม่ต้องเตรียมไฟล์ — วัด 6 อัลกอริทึมที่มีในตัว)

```bash
python algo_lab.py --cores 10 --tdp 15 --grid 500
```

**โหมด B — วัดโปรแกรมอะไรก็ได้** (บอก “คำสั่งที่รันโปรแกรม” ต่อท้าย `--`)

```bash
python perf_bench.py -- python your_program.py
python perf_bench.py --trials 7 -- python train_model.py --epochs 5
```

หรือผ่าน **แดชบอร์ด**: พิมพ์คำสั่ง เช่น `python your_program.py` ลงในช่อง **Target Command** แล้วกด Run Benchmark

- **วัดได้:** โปรแกรมอะไรก็ได้ที่รันด้วยคำสั่ง — สคริปต์ Python, โมเดล AI, ไฟล์ `.exe`, `node app.js` ฯลฯ (วัดจากภายนอกจึงไม่จำกัดภาษา)
- 💡 บน Windows แนะนำใส่ path เต็มของโปรแกรม เพื่อกันปัญหาหาไฟล์ไม่เจอ

## 🔬 เราพิสูจน์ว่าเครื่องมือวัดแม่นได้อย่างไร (Validation)

พิสูจน์ 3 ทาง เพื่อยืนยันว่าค่าที่วัดเชื่อถือได้:

1. **เทียบกับตัวนับของระบบปฏิบัติการ** — เอาค่าหน่วยความจำที่เราวัด ไปเทียบกับค่าที่ Windows บันทึกไว้เอง (ค่าจริง) → ตรงกันเกือบสมบูรณ์ **R² = 1.0000**
   ```bash
   python calibrate_external.py
   ```
2. **เทียบกับทฤษฎี Big-O** — ค่าที่วัดได้จริงตรงกับที่ทฤษฎีทำนาย (เช่น Bubble Sort โตแบบกำลังสอง, Fibonacci เรียกซ้ำโตแบบระเบิด)
3. **ทดสอบซ้ำได้ผลเดิม** — วัดซ้ำ 30 รอบ และรันคนละวัน เกรดออกมาเหมือนเดิมทุกครั้ง

## ⚠️ ข้อจำกัด (Limitations)

เพื่อความโปร่งใส เครื่องมือนี้มีขอบเขตและข้อจำกัดที่ควรทราบ ดังนี้

**สิ่งที่วัดได้ / วัดไม่ได้**
- ✅ วัดได้: โปรแกรมที่ “รันได้ด้วยคำสั่ง” รวมถึงโมเดล AI ขณะทำงาน
- ❌ วัดไฟล์โค้ดที่ไม่รันเองไม่ได้ — ต้องทำให้รันได้ก่อน
- โหมด A วัดเฉพาะ 6 อัลกอริทึมที่มีในตัว (ภาษา Python) — เพิ่มอัลกอริทึมอื่นต้องแก้ไขโค้ด
- โหมด B วัดทั้งโปรแกรมแบบ “กล่องดำ” — บอกภาพรวมได้ แต่ไม่เจาะว่าโค้ดบรรทัดใดกินทรัพยากร
- วัดโมเดล AI ได้เฉพาะทรัพยากรตอนรัน (เวลา/หน่วยความจำ) ไม่ได้วิเคราะห์พารามิเตอร์/FLOPs ภายใน

**ความแม่นยำ**
- ค่าพลังงานเป็น **ค่าประมาณจากการคำนวณ** ไม่ใช่การวัดจากมิเตอร์ไฟจริง — ควรตั้ง `--cores` `--tdp` `--grid` ให้ตรงกับเครื่องและประเทศที่ใช้
- โปรแกรมที่รันเร็วมาก (ระดับไมโครวินาที) อาจวัดคลาดเคลื่อน เพราะชนเพดานความละเอียดของนาฬิกา
- ผลลัพธ์หลัก (% ที่ประหยัด และเกรด A–F) **ไม่ขึ้นกับค่าสัมประสิทธิ์** ที่เลือก แต่ค่าจูลสัมบูรณ์ขึ้นกับการตั้งค่า

**สภาพแวดล้อม**
- ทดสอบยืนยันแล้วบน **Windows** (macOS / Linux ออกแบบรองรับไว้แต่ยังไม่ได้ทดสอบยืนยัน)
- แดชบอร์ดต้องต่ออินเทอร์เน็ต (โหลดไลบรารีกราฟจาก CDN)
